# Domain docs

This repository uses a single domain context.

Before architecture, diagnosis, or test-design work:

1. Read `/CONTEXT.md` for the shared domain vocabulary.
2. Read relevant decisions under `/docs/adr/`.
3. Use the glossary terms rather than inventing synonyms.
4. Surface any proposed change that contradicts an ADR.

Update `CONTEXT.md` when a durable domain concept is introduced. Add an ADR
when a load-bearing architectural choice should not be repeatedly relitigated.
